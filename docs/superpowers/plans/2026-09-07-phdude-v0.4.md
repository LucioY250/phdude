# PhDude v0.4 Co-Author Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.4: the manuscript model, author voice profiles with deterministic learning, the bounded writing context and draft contract, the six writing gates, the `academic-prose` skill with `prose-lint`, `/phdude deslop`, section approval through decisions, and the explainable Academic Prose Quality report.

**Architecture:** Same layering. All gates are pure domain functions over text and the snapshot; the agent writes prose and submits it through the CLI, which is the only writer of `manuscript/`. Text statistics come from one deterministic module with per-language tables. No detector scores anywhere.

**Tech Stack:** Node ≥ 22; no new dependency.

**Spec:** `docs/superpowers/specs/2026-09-07-phdude-v0.4-design.md`

## Global Constraints

- All prior constraints (layering, deps, execFile, atomic writes, one event per mutator, strict flags, typed errors, exit codes, guard, goldens/example regeneration).
- `manuscript/**` is written only by `manuscript submit|approve|reopen` and `deslop --file`; every write runs the gates first; any `block` ⇒ no write, exit 2.
- Never compute, print, or accept an "AI detector" score or target; `prose-lint` must reject options that look like one (`--detector`, `--humanize-to`), with a POLICY error citing PRD §30c.
- Learned voice fields are explicit numbers/lists, never opaque vectors.
- Sentence splitter, tokenizer and language tables live in `src/domain/textstats.js` and are the only text-analysis primitives used by gates, lint, and learn.
- Commit per task with the repo's trailers; do not push.
