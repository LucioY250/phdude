# PhDude v0.4 — Co-Author — Design Spec

**Date:** 2026-09-07
**Status:** Approved for implementation (user directive: finish everything to v1.0)
**Scope source:** `docs/PRD.md` v1.2 §114 (v0.4), §29–§30c, §33, §3.13, §41a–§41b, §70.
**Baseline:** v0.3.0.

---

## 1. Goal

PhDude drafts and revises manuscript sections in the researcher's academic voice, from the workspace's canonical knowledge, through explicit quality gates, and never lets prose outrun evidence. The deterministic core owns the manuscript model, the context budget, the gates that can be computed, the approval flow and the audit trail; the agent owns the prose, guided by the `academic-prose` skill and the author voice profile.

Success condition:

> On the example workspace: `phdude write introduction` assembles a bounded writing context (claims, evidence, questions, voice profile, policy) and hands the agent a draft contract; the agent's draft is submitted through `phdude manuscript submit introduction --file draft.md`; the pipeline runs the deterministic gates (citation audit, evidence fidelity, prose lint, meaning-preservation diff on revision) and either records the section as `draft` with a quality report or rejects it with located findings; `phdude deslop introduction` produces a revision proposal that preserves every claim, citation and number; a researcher approves the section with a decision and it becomes `approved`; `phdude prose introduction` prints an explainable Academic Prose Quality report. Nothing in this version optimizes for or measures AI-detector scores.

## 2. Out of scope

Rendering to DOCX/PDF/LaTeX (v0.6), analysis-driven tables/figures (v0.5), venue adaptation beyond profile validation stubs (v0.6), Research Health aggregation (v0.7). Fresh network calls (v0.3 owns them).

## 3. Deliverables

### 3.1 Manuscript model (PRD §33)

- `manuscript/manuscript.yaml` (`schema: phdude.manuscript`, `version: 1`): `title`, `language`, `voice` (`primary_voice: <author-id>` or `voice: project-consensus`), `target_profile?` (venue pack name; validation only in v0.4), `sections: [{ id, title, file, order, status: planned|draft|revised|approved, hash, claims: [CLAIM ids], questions: [RQ ids], approved_by?: DEC id }]`.
- Sections live as `manuscript/<file>.md` with a small front matter `{ section: <id>, status, hash, updated }`; body is plain Markdown; citations are written as `[@SRC-<id>]` or `[@<bibkey>]` (both resolved against the registry), claims may be annotated `<!-- claim: CLAIM-… -->` at paragraph level; numbers that come from facts/results may be annotated `<!-- fact: FACT-… -->`.
- `phdude manuscript init` creates `manuscript.yaml` with the standard sections (abstract, introduction, methods, results, discussion, conclusions) as `planned`; `manuscript list|show <section>|status`. Section hashes drive incremental gate runs (PRD §35).

### 3.2 Author voice profiles (PRD §30)

- `authors/<id>.yaml` (`schema: phdude.author-profile`, `version: 1`) exactly as PRD §30.1; `authors/samples/<id>/*.md` approved samples referenced by path with `approved: true`.
- `phdude authors list|show <id>|add --json|learn <id> --from <path…>`: `learn` computes deterministic descriptive statistics from approved samples (mean/SD sentence length, sentence-opening diversity, paragraph density, transition-word rate, first-person rate, hedging-word rate, top preserved terminology by TF) and writes them under `learned:` in the profile as explicit, human-readable fields (never embeddings). `project-consensus` = `phdude authors consensus` merges participating profiles (median of numeric fields, union of preserve lists, intersection of avoid lists) into `authors/project-consensus.yaml`, recorded as a Decision when it changes.

### 3.3 Writing context and draft contract (PRD §29, §70)

- `phdude write <section> [--voice <id>] [--budget <tokens≈chars/4>]` assembles `.phdude/cache/writing/<section>/context.md` with, in priority order and within the budget: task instruction (section purpose from the manuscript plan), canonical project facts (title, RQs, methods), the section's claims with state and their strongest evidence (excerpt + locator + bibkey), the citation keys available, the writing policy, the voice profile (learned fields + preserve/avoid lists), and the epistemic-verb table appropriate to each claim's evidence strength (from the `academic-prose` skill references). It prints the context path and the draft contract: what the agent must produce (Markdown for that section only, citations as `[@bibkey]`, one `<!-- claim: -->` per paragraph that asserts a claim, no numbers without a `<!-- fact: -->`/`<!-- result: -->` marker unless they come from a cited source, no new sources). It never writes prose itself.
- The agent writes the draft (skill `academic-prose` + `write`) and submits it: `phdude manuscript submit <section> --file <draft.md> [--revision]`.

### 3.4 Writing pipeline gates (PRD §29.2)

Deterministic gates run at `submit` (and `deslop`), each producing located findings `{ gate, severity: block|warn|info, line, message, hint }`:

1. **Citation audit** (`gate-citations`): every `[@key]` resolves to a SRC (via bibkey or id); every cited SRC exists; no citation of a `dismissed` candidate; `block` on unresolved.
2. **Evidence fidelity** (`gate-evidence`): every `<!-- claim: -->` id exists; a paragraph asserting a claim whose state is `candidate`/`disputed` must use hedged epistemic verbs (table from the skill: candidate → suggests/indicates/is consistent with; supported → shows/provides evidence; canonical → demonstrates allowed); `rejected` claims may not be asserted (`block`); a claim with only `weak` evidence may not use `demonstrates`/`shows` (`block`); numerals ≥ 2 digits without a `fact:`/`result:` marker and not inside a citation sentence → `warn`.
3. **Prose lint** (`gate-prose`, from `skills/academic-prose/scripts/prose-lint.mjs`, pure): transition-word density per paragraph, sentence-length monotony (SD below threshold across ≥ 5 sentences), repeated sentence openings, banned phrases (from `references/ai-writing-patterns.md`, per language), unsupported intensifiers (`significant(ly)`, `crucial`, `robust`, `novel`, `cutting-edge` … without a marker in the sentence), vague literature references (`studies show`, `the literature suggests` without a citation in the sentence), symmetrical list overuse, empty phrases; each as `warn` (or `block` in `ruthless` mode). Output is the observation list plus the six sub-scores of PRD §39.1 (0–100, each derived from counts and documented formulas).
4. **Author voice check** (`gate-voice`): compare the draft's descriptive statistics with the active profile's `learned` fields: sentence length mean/SD, opening diversity, transition rate, first-person rate; report deviations beyond configurable tolerances as `warn`; forbidden words from `terminology.avoid` → `warn`; missing preserved terminology that the claims use → `info`.
5. **Meaning preservation** (`gate-meaning`, on `--revision` and `deslop`): extract from old and new text the multiset of claim ids, citation keys, numerals with their markers, and negation-bearing sentences (sentences containing not/no/never/without/fails to); any removed claim/citation/number or flipped negation → `block`; added claim/citation → `block` unless `--allow-additions`.
6. **Profile validation** (`gate-profile`, only when `target_profile` is set): section presence/order and word limits from the venue pack's `profile.yaml` (v0.6 fills real profiles; v0.4 ships `generic-thesis` with generous limits).

`submit` writes the section file (atomic), updates `manuscript.yaml` (status `draft` or `revised`, hash), stores the report at `.phdude/cache/writing/<section>/report.json` and a canonical summary in `manuscript/reports/<section>.yaml` (scores + counts, no prose), appends one event. Any `block` → nothing is written, exit 2, findings printed with line numbers.

### 3.5 `academic-prose` skill and `/phdude deslop` (PRD §30b)

- `skills/academic-prose/` in the SKILL.md convention with `references/{academic-style,ai-writing-patterns,epistemic-language,voice-matching,examples}.md`, `scripts/prose-lint.mjs` (a thin wrapper over `phdude prose --file <file> [--json]`, which runs the same pure `src/domain/prose-lint.js` used by gate 3), `tests/{academic,ai-slop,human-writing}.yaml` (fixture texts with expected findings, executed by a node:test runner that reads the YAML). Contract: `reads: [manuscript/**, knowledge/claims/**, knowledge/evidence/**, knowledge/sources/**, authors/**, .phdude/writing-policy.yaml]`, `writes: [manuscript/**]` (through `manuscript submit` only), `permissions.network: none`, `quality_gates: [gate-citations, gate-evidence, gate-prose, gate-voice, gate-meaning]`, `approval_gates: [manuscript-approve]`.
- `phdude deslop <section> [--file <revised.md>]`: without `--file`, prints the current prose-lint observations and the revision contract (what to change, what must not change) for the agent; with `--file`, runs gates 1–5 with `--revision` semantics and, if clean, writes the section as `revised` and records the report; the agent never edits the section file directly.
- Language awareness: banned-phrase and transition inventories per language under `references/lang/<code>.md` (en and es shipped); unknown language → language-neutral checks only, reported as `info`.
- The skill and every doc state explicitly: no detector scores, ever (PRD §30c). `prose-lint` refuses any option resembling a detector target.

### 3.6 Approval and audit (PRD §3.4, §82)

- `phdude manuscript approve <section> --decision DEC-x`: the decision must be approved and list `manuscript:<section>` in `affects` (string form allowed by the decision schema? `affects` is `id[]` — ruling: extend the decision schema so `affects` items are ids OR `manuscript:<section-id>`); the section status becomes `approved`, `approved_by` set, hash frozen; a later `submit` on an approved section is refused unless `--reopen` (status back to `revised`, event). Every submit/deslop/approve is an event with the gate summary.

### 3.7 Academic Prose Quality (PRD §39.1)

- `phdude prose <section>|--file <path> [--json]` prints the six sub-scores with the located observations behind each, plus warnings; the aggregate is a documented weighted mean. Stored per section in `manuscript/reports/`. Research Health (v0.7) will read these.

### 3.8 Commands

```
phdude manuscript init|list|show <s>|status|submit <s> --file f [--revision] [--allow-additions]|approve <s> --decision DEC|reopen <s>
phdude authors list|show <id>|add --json|learn <id> --from <paths…>|consensus
phdude write <section> [--voice id] [--budget n]
phdude deslop <section> [--file f]
phdude prose <section>|--file <path> [--json]
```
`next` gains `sections-planned` (medium: manuscript exists, ≥1 section planned and its claims are supported/canonical), `draft-blocked` (high: last submit had blocks), `approval-pending` (medium: revised sections without a decision). `gaps` gains `claim-unwritten` (low: canonical claim not referenced by any section).

## 4. Architecture notes

- Domain: `src/domain/manuscript.js` (section model, hashing, status transitions), `src/domain/gates/{citations,evidence,meaning,voice,profile}.js` (pure), `src/domain/prose-lint.js` (single source of truth). The skill's `scripts/prose-lint.mjs` cannot import the core once the skill is copied into a workspace, so it is a thin wrapper that runs `phdude prose --file <path> [--json]` (the core CLI accepts arbitrary text files, not only manuscript sections). `src/domain/textstats.js` (sentences, words, openings, transitions, hedges; language tables).
- Application: `manuscript.js`, `authors.js`, `write.js`, `deslop.js`, `prose.js`.
- No new dependency. Sentence splitting is a deterministic regex splitter documented with its limits.
- Schemas: `manuscript.json`, `author-profile.json`, `section-report.json`; decision `affects` extended; workspace version stays 2 (all additive; `manuscript/` and `authors/` dirs exist since v0.1).

## 5. Testing

Unit: textstats on fixtures (en/es), each gate with positive/negative fixtures, meaning diff cases (removed citation, flipped negation, changed number), voice deviations, scoring formulas, manuscript transitions. Contract: `academic-prose` skill YAML tests run through the runner; skill contract validates. Integration: write → submit (clean and blocked) → deslop → approve → reopen on a temp workspace; authors learn from sample files; consensus. Golden: `write introduction` context on the example (fixed budget), `prose` report on a committed example section. E2E: the full flow through the CLI.

## 6. Definition of done

Example workspace gains `authors/researcher-a.yaml` with a sample, a manuscript with an approved introduction; README "Writing with PhDude" section; docs (cli, workspace, extending: gate port for packs), CHANGELOG 0.4.0, ADR 0008 writing gates and the no-detector rule; tag v0.4.0.
