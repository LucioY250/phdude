# PhDude v0.2 — Research Brain — Design Spec

**Date:** 2026-09-07
**Status:** Approved for implementation (user directive: finish everything to v1.0)
**Scope source:** `docs/PRD.md` v1.2 §112 (v0.2), plus the v0.1 follow-ups parked at release.
**Baseline:** v0.1.0 (`main` at PR #1 merge).

---

## 1. Goal

Turn the v0.1 knowledge base into a research brain: a workspace can answer *what evidence exists for each question, what is missing, which claims contradict each other, and what the literature looks like as a matrix*, and it can be upgraded safely when schemas change. Everything remains deterministic and field-agnostic; the agent supplies judgment through the same CLI-only write path.

Success condition:

> On the example workspace and on a fresh bootstrapped project, `phdude gaps`, `phdude matrix` and `phdude cite check` produce correct, explainable output; a claim can be marked as contradicting another and both surface as `disputed`; `phdude migrate` upgrades a v0.1 workspace to v0.2 schemas without losing information; every skill's `phdude:` contract is validated and its permissions reported.

## 2. Out of scope for v0.2

Network access of any kind (v0.3), writing (v0.4), analysis (v0.5), rendering (v0.6), review skills and Research Health scoring (v0.7). Vector search, embeddings.

## 3. Deliverables

### 3.1 Schema migration system (PRD §58–§59)

- `phdude.yaml` gains `workspace_version: 2` (v0.1 workspaces lack the field and are treated as version 1).
- `migrations/` in the package: one module per step, `NNNN-<slug>.mjs` exporting `{ from: 1, to: 2, describe(), apply(store) → { changed: string[] } }`. Migrations are deterministic, idempotent, and operate through `FsStore` only.
- `phdude migrate [--dry-run]`: reports the chain, refuses to run on a dirty git tree unless `--force` (git is the backup), applies steps in order, rewrites `workspace_version`, appends one event per step. `--dry-run` lists what would change.
- `phdude doctor` and every read command report `workspace needs migration (1 → 2)` and refuse to write (USAGE, hint `phdude migrate`) when the workspace version is behind; reads still work.
- Migration 0001 (1 → 2): add `provenance` defaults to claims/evidence (see 3.5), add `contradicts: []` to claims, add `workspace_version`. Tested against a committed v0.1 fixture workspace (`tests/fixtures/workspaces/v0.1-minimal/`).

### 3.2 Skill contract schema and permission reporting (PRD §41b, §76)

- `schemas/skill.json`: JSON Schema for the `phdude:` front-matter block: `version: 1`, `reads[]`, `writes[]`, `objects[]?`, `artifacts[]?`, `evidence_requirements?`, `provenance?`, `approval_gates[]?`, `quality_gates[]?`, `permissions: { network: 'none'|'allowed', workspace: string[] }`, `dependencies[]?`, `tests?`. `additionalProperties: false` inside `phdude`.
- `src/adapters/skills/loader.js`: `loadSkill(dir)` parses front matter, validates the `phdude:` block, returns `{ name, description, contract, path }`; a skill without a `phdude:` block gets default least privilege `{ reads: [], writes: [], permissions: { network: 'none', workspace: ['read'] } }` and a warning. `discoverSkills(roots)` (package `skills/`, pack skills, `<workspace>/.phdude/skills/`).
- Enforcement in v0.2: `init` refuses to install a skill whose contract fails validation; `doctor` lists every installed skill with its permissions; `.phdude/research-policy.yaml` gains `skills: { allow_network: false }` and any skill declaring `network: allowed` is rejected unless the policy allows it. Contract tests: every shipped skill (core and packs) validates.

### 3.3 Citation registry (PRD §37 subset, offline)

- `SRC` objects gain optional `bibkey` (deterministic: `<firstAuthorSurname><year><firstTitleWord>` lowercased ASCII, uniqueness enforced with `-2`, `-3` suffixes at export time), `abstract?`, `keywords[]?`, `identifiers: { doi?, isbn?, arxiv?, pmid?, url? }` (DOI regex `^10\.\d{4,9}/\S+$`).
- `phdude cite list` (table), `phdude cite check` (every source cited by at least one evidence item; every evidence item's source exists; DOI format; missing year/authors/title; duplicate sources by normalized title+year), `phdude cite export --format bibtex|csl-json` writes `references.bib` / `references.json` deterministically. The registry is derived, never canonical.
- Claims/evidence do not change; the "citation" is the SRC id.

### 3.4 Literature matrix and research gaps (PRD §112)

- `phdude matrix [--format md|csv] [--question RQ-n]` (`--json` gives the row objects): one row per source: bibkey, year, type, role in project (which RQs its evidence supports, via evidence → claim → question), claims supported (count and ids), strongest evidence strength, facts extracted from its artifacts, packs-declared method tags if present in `ext`. Deterministic ordering (year desc, bibkey).
- `phdude gaps [--json]`: explainable gap report grouped by type: questions with no claims; questions whose claims are all `candidate`; claims with no evidence; claims supported only by `weak` evidence; hypotheses with no supporting or contradicting claim; sources never cited; artifacts with no extracted entities (role set but no facts/sources reference them); open conflicts; disputed claims. Each gap has `id`, `kind`, `why`, `command`. `next` gains rule `gaps` (medium) pointing at `phdude gaps` when ≥3 gaps exist and no higher rule fires.

### 3.5 Provenance and claim contradictions (PRD §20–§21, §38)

- Claims and evidence gain `provenance: { method: 'agent-extraction'|'manual'|'imported', derived_from: id[] }`; `addEntity` defaults `method` from the actor (`agent === 'cli'` → manual, else agent-extraction) and `derived_from` from the referenced artifacts/sources. `knowledge trace` prints provenance lines.
- Claims gain `contradicts: id[]`. `phdude link <CLAIM-a> --contradicts <CLAIM-b>` records the relation on both claims (symmetric), sets both to `disputed` if they were `candidate`/`supported`/`canonical` (canonical → disputed is allowed by the state machine and needs no decision, PRD §3.3 proactive), appends one event, and refuses self-links. `status` lists disputed pairs; `gaps` includes them; the lineage graph gains `contradicts` edges (undirected, rendered once).
- Resolution: a decision whose `change` carries `resolves_contradiction: [CLAIM-a, CLAIM-b]` and `survivor: CLAIM-a`, once approved, lets `promote` move the survivor back to `supported`/`canonical` only after every other claim it contradicts in that list is `rejected` (`promote --to rejected`, no decision needed). Promoting a non-survivor with that decision is refused; a decision without `survivor` resolves nothing. The gate keys on the `contradicts` relation, not on the current state: while a claim has a live contradiction (a contradicted claim that is not `rejected`), its only reachable states are `rejected` (no decision) or `supported`/`canonical` through the survivor decision; moving it to `candidate` or `disputed` by hand is refused. Disputed pairs are reported while both sides are unrejected. A workspace whose `workspace_version` is newer than the installed PhDude is refused for writes.

### 3.6 New entity: Method (PRD §18)

- `METH-<hash10>` in `research/methods/`: `name`, `design` (free text), `paradigm` (`quantitative|qualitative|mixed|computational|theoretical|archival|other`), `sampling?`, `instruments[]?`, `analysis[]?`, `limitations[]?`, `questions[]`, `state`. Added via `add method`; linked via `link RQ-n --to METH-…`? No: the method references questions; `link METH-x --to RQ-n` adds to `questions`. Included in status counts, gaps (questions with no method), matrix (method tags), lineage (`method → question: addresses`).

### 3.7 v0.1 parked follow-ups closed in v0.2

- `ingest .` no longer walks `knowledge/`, `research/`, `decisions/`, `.phdude/`, `phdude.yaml`; only `sources/` and explicit paths outside those dirs.
- Ingest path containment adds a `realpath` re-check.
- `supersede --by <researcher> --with <DEC-id>` replaces the overloaded flag; the old form errors with a hint.
- `disputed` is produced automatically by contradictions (3.5).
- Strict flag parsing: unknown `--flags` are USAGE errors (`parseArgs strict: true` with the full option table per command).
- Migration path exists (3.1); id materials are frozen for the remainder of 0.x unless a migration ships with the change.

## 4. Architecture notes

- New ports: none that touch the network. `SkillLoader` is an adapter over the filesystem.
- New application modules: `migrate.js`, `cite.js`, `matrix.js`, `gaps.js`; `link.js` extended; `add.js` extended (method, provenance).
- Domain: `gaps.js` (pure), `matrix.js` (pure), `bibtex.js` (pure formatter), `contradictions.js` (pure), `migrations` are application-level with a domain `versionChain(from, to, steps)` helper.
- Schemas bump: claim, evidence, source, project to `version: 2`? No — keep `version: 1` on objects and version the *workspace* (`workspace_version`); object schema `version` increments only on breaking changes to that object, and none of 3.x are breaking (all additive with defaults). Migration 0001 still runs to add defaults so readers can rely on fields.
- Skills to update: `phdude-core` (new commands, provenance rule, contradictions), `knowledge` (trace provenance), `bootstrap` (record methods, contradictions), `decisions` (contradiction resolution). New skill `literature` (how to read `matrix` and `gaps`, when to ask the researcher, never invent sources).
- Commands (slash) added: `phdude-cite`, `phdude-matrix`, `phdude-gaps`, `phdude-migrate`.

## 5. Testing

Unit: bibtex formatting (golden), bibkey derivation and collision suffixes, gaps rules, matrix rows, contradiction symmetry and state changes, version chain. Contract: skills (core + packs) validate against `schemas/skill.json`; migrations are idempotent (apply twice = once). Integration: migrate a committed v0.1 fixture workspace; cite export writes deterministic files; link --contradicts end to end. Golden: `matrix --format md` and `gaps` on `examples/generic-thesis` (example regenerated with a method, a contradiction, and a never-cited source). E2E: `migrate --dry-run` on a v0.1 fixture, `cite check` failing then passing, `gaps` JSON shape, strict flags.
