# PhDude v0.5 Analysis & Visualization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.5: execution policy and AnalysisRunner port, datasets with profiles, declared analyses that produce RESULT objects, reproducible tables and figures with lineage and alt text, `repro check`, migration 0002, and the analysis/figures skills.

**Architecture:** Same layering. Scripts run only through the runner adapter (`execFile`, no shell, minimal env, timeout) and only when the execution policy allows. Results, tables and figures are entity-per-file objects whose runs record input/output hashes; staleness is a pure graph computation.

**Tech Stack:** Node ≥ 22; no new dependency; Node is the only runtime CI requires.

**Spec:** `docs/superpowers/specs/2026-09-07-phdude-v0.5-design.md`

## Global Constraints

- All prior constraints (layering, deps, `execFile` only, atomic writes, one event per mutator, strict flags, typed errors, exit codes, guard, goldens/example regeneration, surface test, skill contracts).
- No execution without `execution.enabled` or `--allow-exec`; every run → one `analyze`/`figure` event; scripts get a minimal env and `cwd` = workspace root; timeout from policy.
- Ids: `DATASET-<hash10 of bytes>`, `ANALYSIS-<hash10 of "analysis\n"+name>`, `TABLE-…name`, `FIG-…name`, `RESULT-<hash10 of "result\n"+summary+"|"+analysis id>` (amend `newResult` id material to include `from` when present; migration 0002 does NOT rewrite existing results).
- Workspace version → 3; migration 0002 adds policy keys (`execution`, `skills.allow_execution`) when missing and the output dirs; idempotent.
- Commit per task with the repo's trailers; do not push.
