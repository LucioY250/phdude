# PhDude v0.2 Research Brain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.2: workspace versioning and migrations, validated skill contracts with permission reporting, an offline citation registry, literature matrix, research gaps, provenance, claim contradictions, the Method entity, strict CLI flags, and the v0.1 parked follow-ups.

**Architecture:** Same modular monolith as v0.1 (domain pure, application over ports, adapters at the edge, CLI-only writes). All v0.2 features are additive to schemas with defaults; the workspace carries `workspace_version` and `phdude migrate` applies ordered, idempotent steps through `FsStore`.

**Tech Stack:** Node ≥ 22, ESM, `yaml`, `ajv`, `fflate`; `node:test`; prettier + eslint.

**Spec:** `docs/superpowers/specs/2026-09-07-phdude-v0.2-design.md`

## Global Constraints

- All v0.1 Global Constraints still apply (layering test, three runtime deps, `execFile` only, atomic writes, one event per mutating use case, exit codes 0/1/2/3/4, typed errors with hints, prettier settings).
- No network access anywhere in v0.2.
- Object schemas stay at `version: 1`; new fields are optional with defaults applied by migration 0001 and by factories. `phdude.yaml` gains `workspace_version` (integer, current = 2).
- Ids: `METH-<10hex>` of `method + "\n" + normalized name`. Existing id materials unchanged.
- Every new command has: application module, CLI command module, `help` entry, `docs/cli.md` section, slash command in `commands/`, README table row, and `--json` output.
- Regenerate `examples/generic-thesis` (script) and goldens whenever output changes; keep make-example parity tests green.
- Commit per task with the repo's trailers; do not push (controller pushes).

### Task 1: Workspace versioning and `phdude migrate`

**Files:** `src/domain/versioning.js`, `migrations/0001-workspace-v2.mjs`, `src/application/migrate.js`, `src/adapters/cli/commands/migrate.js`, `commands/migrate.md`, `schemas/project.json` (+`workspace_version`), `schemas/claim.json` (+`provenance`, `contradicts`), `schemas/evidence.json` (+`provenance`), `tests/fixtures/workspaces/v0.1-minimal/**` (a committed v0.1 workspace: phdude.yaml without workspace_version, 1 artifact, 1 source, 1 evidence, 1 claim, 1 fact, 1 RQ, events.jsonl), `tests/unit/domain/versioning.test.js`, `tests/integration/migrate.test.js`, `tests/e2e/cli.test.js` (+migrate --dry-run case), `docs/adr/0006-workspace-versioning-and-migrations.md`.

**Interfaces:**
- `versioning.js`: `CURRENT_WORKSPACE_VERSION = 2`; `workspaceVersionOf(project) → number` (missing → 1); `planChain(steps, from, to) → step[]` (throws `PhdudeError('VALIDATION')` on a gap); `needsMigration(project) → boolean`.
- Migration module: `export default { from: 1, to: 2, describe: () => string, async apply(store) → { changed: string[] } }` — idempotent: adds `provenance: { method: 'imported', derived_from: [] }` where missing on claims/evidence, `contradicts: []` on claims, writes `workspace_version: 2`.
- `migrate(deps, { dryRun, force }) → { from, to, steps: [{ from, to, description, changed }], applied: boolean }`; refuses on dirty git tree unless `force` (`git.isDirty(root)` added to `src/adapters/git.js`); one event per applied step `{ op:'migrate', ids:[], summary:'1 → 2: …' }`.
- Read guard: `loadSnapshot` returns `warnings` including `workspace needs migration (1 → 2)`; a shared `assertUpToDate(store)` in `src/application/guard.js` throws `PhdudeError('USAGE', 'workspace needs migration (1 → 2)', 'run phdude migrate')` and is called by every mutating use case (add, link, decide, promote, ingest, packs apply, mode).

- [ ] Write the v0.1 fixture workspace by hand (small, realistic, ids valid per the v0.1 rules; no `workspace_version`).
- [ ] Tests first: chain planning (1→2 ok, 1→3 with missing step throws), migrate on the fixture copied to a temp dir: dry-run changes nothing and lists files; apply rewrites the listed files, sets `workspace_version: 2`, appends one event; second apply is a no-op (no changes, no event); mutating command on an un-migrated workspace exits 1 with the hint; read commands still work.
- [ ] Implement; wire `migrate` into the CLI and help; ADR 0006; commit `feat(migrate): workspace versioning and migration 0001`.
