# PhDude v0.1 — Design Spec

**Date:** 2026-09-07
**Status:** Approved for implementation (user directive: analyze → plan → build → ship)
**Scope source:** `docs/PRD.md` v1.2, §111 (MVP v0.1)

---

## 1. Goal

Ship the v0.1 MVP defined in PRD §111:

> A messy research workspace from any supported discipline can be ingested and PhDude can explain what the project is, what is known, what conflicts exist, and what should happen next without assuming the project's field or methodology.

v0.1 is a **deterministic harness plus agent skills**. The deterministic runtime (Node ESM CLI) owns inventory, hashing, text extraction, canonical storage, validation, lineage, conflict detection, status, and next-action scoring. The AI agent (Claude Code, Codex) owns judgment: classifying artifacts, extracting claims/facts/questions, and proposing decisions. The agent writes into the workspace **only through the CLI**, so every canonical object is validated, hashed, attributed, and logged.

## 2. Out of scope for v0.1

Fresh literature search, provider adapters, freshness tracking, writing engine, author voice, templates, rendering (DOCX/PDF/LaTeX), analysis execution, figures/tables, Research Health scoring, review modes beyond a mode flag, migrations beyond schema version stamping, plugin permission manifests. These are v0.2+ and must remain addable without touching the domain core.

## 3. Architecture

Modular monolith, hexagonal, functional core / imperative shell.

```
phdude/
├── bin/phdude.js                 # CLI entry (imperative shell)
├── src/
│   ├── domain/                   # pure: entities, ids, states, lineage, conflicts, scoring
│   ├── application/              # use cases; depend on ports only
│   ├── ports/                    # documented JS interfaces (JSDoc) + contract test suites
│   └── adapters/
│       ├── store/fs              # YAML/JSON/JSONL on disk, atomic writes
│       ├── documents/            # text, markdown, ooxml (docx/pptx/xlsx), pdf (pdftotext CLI)
│       ├── agents/               # claude-code, codex host-file generators
│       └── cli/                  # argument parsing, output formatting (text/json)
├── schemas/                      # JSON Schema for every canonical object + config
├── packs/{fields,methods}/       # example packs; pack.yaml + skill markdown
├── skills/                       # host-agnostic markdown skills installed into workspaces
├── commands/                     # slash-command templates (Claude Code) — thin wrappers
├── examples/generic-thesis/      # e2e fixture workspace
├── tests/{unit,contracts,integration,golden,e2e}/
└── docs/adr/
```

**Dependency rule:** `domain` imports nothing from `application`, `ports`, or `adapters`. `application` imports `domain` and `ports`. `adapters` import `ports` (and `domain` types). `bin` wires adapters into use cases. A unit test enforces this by scanning imports.

**Runtime deps (core):** `yaml`, `ajv` (schema validation), `fflate` (OOXML unzip). Argument parsing uses `node:util.parseArgs`. PDF text extraction shells out to `pdftotext` when available (structured `execFile`, no shell interpolation); when absent, the artifact is still inventoried and hashed, and the CLI reports an actionable message.

**Dev deps:** `prettier`, `eslint` (flat config, `@eslint/js` recommended). Tests use `node:test` only.

## 4. Research workspace layout (what `phdude init` creates)

```
my-research/
├── phdude.yaml                   # project config (schema: phdude.project v1)
├── AGENTS.md                     # shared agent instructions (Codex + any host)
├── CLAUDE.md                     # Claude Code entry; includes AGENTS.md content + host notes
├── .claude/commands/phdude*.md   # slash commands wrapping the CLI
├── .phdude/
│   ├── constitution.yaml
│   ├── research-policy.yaml
│   ├── writing-policy.yaml
│   ├── citation-policy.yaml
│   ├── methodology-policy.yaml
│   ├── publication-policy.yaml
│   ├── author-profile.yaml
│   ├── skills/<name>/SKILL.md    # copied skills (open Agent Skills convention, host-agnostic)
│   ├── events.jsonl              # append-only audit log (canonical, committed)
│   └── cache/                    # disposable, gitignored
├── authors/                      # per-researcher voice profiles (PRD §30.1; populated in v0.4)
├── sources/                      # raw research materials the user drops in
├── knowledge/
│   ├── artifacts/  ART-*.yaml
│   ├── sources/    SRC-*.yaml    # bibliographic sources (papers, reports, etc.)
│   ├── claims/     CLAIM-*.yaml
│   ├── evidence/   EVID-*.yaml
│   ├── facts/      FACT-*.yaml   # project facts (sample size, dates, tools…) with provenance
│   └── results/    RESULT-*.yaml
├── research/
│   ├── questions/  RQ-*.yaml
│   └── hypotheses/ H-*.yaml
├── decisions/      DEC-*.yaml
├── data/ analysis/ figures/ tables/ manuscript/ templates/ outputs/   (empty, with .gitkeep)
└── .gitignore                    # .phdude/cache/, .env
```

Entity-per-file, YAML, schema-versioned (`schema: phdude.claim`, `version: 1`). `init` runs `git init` if the directory is not already inside a repository. `init` is idempotent: existing files are never overwritten; missing ones are added and reported.

## 5. Canonical objects (field-agnostic)

Every object has: `schema`, `version`, `id`, `created` (ISO), `actor` (`{researcher, agent}`), `state` (where applicable), and free-form `tags[]`. Packs may add fields under `ext.<pack>` only; core schemas allow `ext` as an open object.

| Object | ID | Key fields |
|---|---|---|
| Artifact | `ART-<hash10>` | `path`, `hash` (sha256), `bytes`, `mime`, `kind` (`pdf/docx/pptx/xlsx/csv/md/txt/bib/tex/other`), `extracted` (`{status, text_chars, sections, tables, method}`), `role` (`paper/thesis-draft/presentation/dataset/questionnaire/notes/report/unknown`, agent-set) |
| Source | `SRC-<hash10>` | `title`, `authors[]`, `year`, `venue`, `doi`, `url`, `type` (`article/book/chapter/thesis/report/preprint/web/dataset/other`), `artifacts[]`, `state` |
| Claim | `CLAIM-<hash10>` | `statement`, `kind` (`literature/empirical/theoretical/methodological`), `state`, `supported_by[]` (EVID ids), `questions[]` (RQ ids), `sections[]` |
| Evidence | `EVID-<hash10>` | `source` (SRC or ART or RESULT id), `locator` (page/section/table/quote), `excerpt`, `strength` (`strong/moderate/weak/unknown`), `state` |
| Fact | `FACT-<hash10>` | `key` (normalized, e.g. `sample_size`), `value`, `unit?`, `from` (ART id + locator), `state` |
| ResearchQuestion | `RQ-<n>` | `text`, `objectives[]`, `state` |
| Hypothesis | `H-<n>` | `text`, `questions[]`, `state` |
| Result | `RESULT-<hash10>` | `summary`, `from` (analysis/artifact ref), `values{}`, `state` |
| Decision | `DEC-<hash10>` | `title`, `rationale`, `proposed_by`, `approved_by[]`, `status` (`proposed/approved/rejected/superseded`), `change` (object-level diff description), `affects[]` |

**ID strategy:** content-derived, stable, merge-safe.
- Artifact: sha256 of file content → first 10 hex.
- Claim/Evidence/Fact/Source/Result/Decision: sha256 of `type + "\n" + normalized primary text` (statement / excerpt / key+value+source artifact / title+year / summary / title) → first 10 hex. Re-adding the same claim is a no-op (idempotency). A Fact's identity includes its source artifact so the same value reported by two artifacts is two Fact records (needed for PRD §38 conflict reporting).
- RQ/H: sequential (`RQ-1`, `RQ-2`) because they are few and human-facing; collisions across branches are detected on load and reported, never silently merged.

**Knowledge states:** `canonical | supported | candidate | disputed | rejected` (PRD §19). Agent-created objects default to `candidate`. Promotion to `canonical` requires an approved Decision referencing the object (PRD §34 human authority). The CLI enforces this: `phdude promote CLAIM-x --decision DEC-y` fails unless DEC-y is `approved` and lists the object in `affects`.

## 6. Events (audit trail)

`.phdude/events.jsonl`, append-only, one JSON object per line:
```json
{"ts":"…","op":"ingest","actor":{"researcher":"lucio","agent":"claude-code"},"ids":["ART-…"],"summary":"…"}
```
Every mutating use case appends exactly one event. Git history complements it.

## 7. Ingestion pipeline (`phdude ingest [paths…]`, default `sources/`)

```
DISCOVER  → walk paths, skip ignored (node_modules, .git, .phdude/cache)
INVENTORY → stat + sha256 + kind detection (extension + magic bytes for pdf/zip)
DEDUP     → same hash under different paths ⇒ one Artifact, multiple `paths[]`
EXTRACT   → DocumentParser by kind ⇒ text + sections + tables (best effort)
CACHE     → .phdude/cache/<ART-id>/{manifest.json,text.md,sections/*.md,tables/*.csv}
VERSIONS  → same stem, different hash ⇒ `versions_of` link (newest by mtime flagged `latest`)
RECORD    → knowledge/artifacts/ART-*.yaml (atomic write) + event
```

Unchanged hash ⇒ skip extraction (cache hit). Extraction is best-effort with per-artifact status; a failed table extraction never fails the run. `--json` prints the full inventory for agent consumption.

**DocumentParser port:** `{ kinds: string[], parse(buffer, {path}) → {text, sections[], tables[], meta, warnings[]} }`. Adapters: `text` (txt/md/csv/bib/tex), `ooxml` (docx paragraphs+headings+tables; pptx slide text; xlsx sheets→tables), `pdf` (pdftotext -layout; `available()` probe). A shared contract test runs every adapter against fixtures.

Classification (role) and entity extraction (claims, facts, sources) are **agent work**, driven by the `bootstrap` skill, which reads cached text section by section (never whole-project reads) and writes via `phdude add`.

## 8. Contradiction detection (deterministic)

Over `knowledge/facts/`: group by normalized `key`; if values differ across distinct `from` artifacts and no approved Decision resolves the key ⇒ conflict `{key, values:[{value, from}], resolution: null}`. Reported by `status` and fed to `next`. Resolution = an approved Decision with `change.fact_key` and `change.canonical_value`. Same logic later extends to claims marked `disputed`.

## 9. Packs

`packs/fields/<name>/pack.yaml` and `packs/methods/<name>/pack.yaml`, schema `phdude.pack v1`:
```yaml
schema: phdude.pack
version: 1
name: quantitative
kind: method            # field | method
description: …
terminology: [ … ]
detect:
  keywords: [regression, p-value, sample, survey]   # for recommendation only
reviewers: [statistician]
recommended_checks: [assumption-checks, effect-sizes]
skills: [skills/analysis-quantitative.md]           # relative to pack dir
schemas: []                                         # optional extra JSON Schemas (ext.<pack>)
```
Registry loads packs named in `phdude.yaml` (`fields[]`, `methods[]`) from the built-in `packs/` dir, then from `.phdude/packs/` in the workspace. Unknown pack ⇒ explicit error. `phdude packs detect` scores keyword hits across cached text and prints recommendations; `phdude packs apply <name>` edits `phdude.yaml` and records an event; nothing is applied silently.

Ship minimal but real packs: fields `computer-science`, `business`, `medicine`, `humanities`; methods `quantitative`, `qualitative`, `systematic-review`. Contract test: every shipped pack validates and every referenced skill file exists.

## 10. Agent adapters

`AgentHost` port: `{ name, install(workspace, {skills, commands}) → files written }`.
- **claude-code:** writes `CLAUDE.md` (imports AGENTS.md by reference + Claude notes), `.claude/commands/phdude-<cmd>.md` for each PRD §44 command in v0.1 scope (`bootstrap, ingest, status, next, knowledge, packs, add, decide, doctor`, mode `lite|full|ruthless|off`).
- **codex:** writes `AGENTS.md` (skills inlined via section headers, command reference).
Both share the same skill markdown under `skills/`; host files are thin. `phdude init --agents claude-code,codex` (default: both).

Skills shipped in v0.1 (`skills/<name>/SKILL.md`, front matter `name`, `description`, `phdude:` contract block per PRD §41b): `phdude-core` (operating rules, epistemic states, never fabricate, write only via CLI), `bootstrap` (classify + extract workflow, section-by-section budgeted reads), `knowledge` (how to query/trace), `decisions` (propose/approve protocol), `next` (how to present and act on recommendations), `review-modes`.

## 11. Status and Next

`phdude status [--json]` prints: project (title, fields, methods, outputs, mode), inventory (artifacts by kind, extraction status), knowledge counts by type and state, open conflicts, pending decisions, latest events. Every number is derived on read from files (no cached state).

`phdude next [--json]` runs a pure scoring function over a `WorkspaceSnapshot`. Rules (each yields `{action, why[], impact: high|medium|low, command}`):
1. No research questions ⇒ define RQ.
2. Artifacts with `extracted.status != ok` ⇒ fix extraction (tool install hint).
3. Artifacts with `role: unknown` ⇒ run bootstrap classification.
4. Open fact conflicts ⇒ resolve via decision (weight × dependents).
5. Canonical/supported claims with no evidence ⇒ attach evidence.
6. Candidate claims ≥ 5 ⇒ review and promote/reject.
7. Recommended packs not applied ⇒ apply packs.
8. Proposed decisions awaiting approval ⇒ approve/reject.
9. RQs with zero claims ⇒ literature/evidence gap.
10. Otherwise ⇒ "workspace consistent; next cycle: new sources".
Ordering: impact, then dependent count, then rule order. Output always explains **why** (PRD §45).

## 12. CLI surface (v0.1)

```
phdude init [dir] [--title] [--agents claude-code,codex] [--no-git]
phdude bootstrap            # ingest + packs detect + status + next + agent handoff instructions
phdude ingest [paths…] [--force]
phdude status
phdude next
phdude knowledge list [--type] [--state] [--query]
phdude knowledge show <id>
phdude knowledge trace <id>          # lineage graph up and down
phdude add <claim|evidence|fact|source|question|hypothesis|result> (--json '<obj>' | --file f.json)
phdude decide propose --title --rationale --affects ID… --change '<json>'
phdude decide approve <DEC-id> [--by researcher]
phdude promote <id> --decision <DEC-id>
phdude packs list|detect|apply <name>
phdude mode lite|full|ruthless|off
phdude doctor                        # adapters available, cache, schema versions, git state
```
Global flags: `--json`, `--workspace <dir>`, `--actor researcher=<name>,agent=<host>` (defaults: git user.name, env `PHDUDE_AGENT`). Exit codes: 0 ok, 1 usage, 2 validation, 3 policy violation (e.g. promote without approved decision), 4 external tool missing.

## 13. Error handling

Errors are typed (`PhdudeError{code, message, hint}`), printed as `message` + `Suggested action:` line; `--json` emits `{error:{code,message,hint}}`. Optional adapters degrade independently. No swallowed errors; warnings are collected per operation and printed.

## 14. Testing

- **Unit:** ids, hashing, normalization, schemas (valid + invalid fixtures per object), state transitions, conflict detection, next-action scoring, dependency rule (import layering).
- **Contract:** DocumentParser (all adapters × fixtures), AgentHost (both hosts produce required files), Pack (all shipped packs).
- **Integration:** fs store atomic writes, ingest on a fixture dir with pdf/docx/pptx/xlsx/md, git init behavior.
- **Golden:** `status` and `next` text output for `examples/generic-thesis`.
- **E2E:** `init → ingest → add → decide → promote → status → next` on a temp dir through `bin/phdude.js`.

CI (GitHub Actions): `npm ci`, `prettier --check`, `eslint`, `node --test`, schema validation of `packs/` and `examples/`.

## 16. Definition of done for v0.1

`npx phdude init` on an empty dir, drop a PDF + DOCX + PPTX + XLSX into `sources/`, run `/phdude bootstrap` in Claude Code or Codex, and the agent can answer: what the project is, what is known (claims with evidence), what conflicts exist (fact conflicts), and what to do next (`phdude next`), with all writes validated and logged, and the whole suite green in CI.
