# PhDude v0.3 — Research Engine — Design Spec

**Date:** 2026-09-07
**Status:** Approved for implementation (user directive: finish everything to v1.0)
**Scope source:** `docs/PRD.md` v1.2 §113 (v0.3), §15, §22–§24, §71–§77.
**Baseline:** v0.2.0.

---

## 1. Goal

PhDude can go and find current literature for each research question, under an explicit, auditable network policy; the researcher reviews candidates and accepts them into the source registry; the workspace knows when a search has gone stale. Nothing leaves the machine except the query text, and nothing is written to the knowledge base without a human-visible step.

Success condition:

> With `network.enabled: true` (or `--allow-network`), `phdude research "…" --question RQ-1` returns deduplicated candidates from at least two providers, stores them as `CAND-*` objects, and records the search; `phdude research accept CAND-x` creates a `SRC-*` with identifiers; `phdude freshness` reports the age of every question's last search and flags stale ones per policy; `phdude research-fresh` re-runs stale searches and reports only new candidates; with network disabled every network command refuses with a clear hint. All of it is testable offline through recorded provider fixtures.

## 2. Out of scope

Full-text retrieval or PDF download (never automatic; v0.6 may add opt-in), embeddings, LLM ranking, writing (v0.4), analysis (v0.5).

## 3. Deliverables

### 3.1 Network policy and audit (PRD §71–§77)

- `.phdude/research-policy.yaml` gains:
  ```yaml
  network:
    enabled: false            # nothing leaves the machine unless true
  providers: [openalex, crossref, arxiv]   # ordered; others available: semantic-scholar, pubmed
  research:
    year_range: { from: 2021 }
    languages: [en]
    peer_reviewed: preferred  # preferred | required | any
    preprints: { require_approval: true }
    freshness: { stale_after_days: 180 }
    limit: 20
  ```
- A network call is allowed only when `network.enabled` is true or the command carries `--allow-network`; otherwise `PhdudeError('POLICY', 'network access is disabled', 'set network.enabled: true in .phdude/research-policy.yaml or pass --allow-network')`.
- Every provider call appends one event `{ op: 'search', ids: [SEARCH-id], summary: '<provider>: "<query>" → N results' }`. What leaves the machine per call, and nothing else: the query text, the result limit, the `from` year filter, a `phdude/<version>` User-Agent, the optional `mailto` from the author profile (OpenAlex, Crossref), and an API key when configured (`PHDUDE_S2_API_KEY` as a header to Semantic Scholar; `PHDUDE_NCBI_API_KEY` as NCBI's documented `api_key` query parameter to PubMed). All provider URLs are HTTPS. `--provider` can only narrow the policy's `providers` list, never widen it. The event never stores result payloads and keys never appear in errors or events. API keys (Semantic Scholar) come from `PHDUDE_S2_API_KEY`; Crossref/OpenAlex use a polite `mailto` from `.phdude/author-profile.yaml` `email` if present.
- `doctor` prints the network policy and the configured providers; it never calls the network.

### 3.2 SearchProvider port and adapters (PRD §22, §48, §85)

- Port `src/ports/search-provider.js`: `{ name, requiresKey?: string, async search(query, { from, limit, signal }) → Candidate[] }`; `Candidate = { provider, external_id, title, authors: string[], year: number|null, venue: string|null, doi: string|null, url: string|null, abstract: string|null, type: 'article'|'preprint'|'book'|'chapter'|'other', open_access: boolean|null, cited_by: number|null }`. Contract suite `searchProviderContract(test, assert, provider, { fetch })` checks: normalized shape, `from` filter honored, `limit` honored, empty result → `[]`, HTTP 429/5xx → `PhdudeError('TOOL_MISSING'|'VALIDATION')` with provider name, malformed JSON → typed error, abort signal respected.
- Adapters in `src/adapters/search/`: `openalex.js` (`/works?search=…&filter=from_publication_date:…`), `crossref.js` (`/works?query=…&filter=from-pub-date:…`), `arxiv.js` (Atom XML via the existing regex walker), `semantic-scholar.js` (`/graph/v1/paper/search`, optional key), `pubmed.js` (esearch + esummary). All use global `fetch` injected through deps (`deps.fetch`) so tests pass a fake; timeouts 15 s via `AbortController`; one retry on 429/503 with backoff ≤ 2 s; User-Agent `phdude/<version> (+https://github.com/LucioY250/phdude)`. Responses are untrusted: validate before mapping.
- Fixtures: recorded JSON/XML responses per provider under `tests/fixtures/search/`, served by a `fakeFetch(routes)` helper; live tests behind `PHDUDE_LIVE_TESTS=1` and skipped in CI.

### 3.3 Candidates and searches (PRD §113 candidate review)

- `CAND-<hash10>` of `candidate + "\n" + identityKey` where identityKey is `doi:<lowercase doi>` when any provider reports a DOI, else `title:<normalized title>|<year>` — stable across provider order and subsets — in `knowledge/candidates/`: candidate fields plus `query`, `question?` (RQ id), `search` (SEARCH id), `state: candidate|accepted|dismissed`, `reason?`, `accepted_as?` (SRC id).
- `SEARCH-<hash10>` of `search + "\n" + normalized query + "|" + question` in `research/searches/`: `query`, `question?`, `providers[]`, `filters`, `runs: [{ at, provider, count, new }]`, `last_run`.
- Cross-provider dedup: same DOI (case-insensitive) or same normalized title + year ⇒ one candidate; providers merged into `providers[]`, first provider's `external_id` kept, extra ids under `ext.ids`; null-only fields (doi, url, venue, abstract, year, cited_by, open_access) are filled from later providers.
- Filters applied client-side after the provider filter: year_range, language when the provider reports it, preprints flagged (`type: preprint`) and, with `require_approval`, listed but marked `needs_approval: true`.
- Ranking: deterministic score = provider rank position (inverse) + cited_by log-scaled + year recency; explained in `--json` as `score_parts`.

### 3.4 Commands

```
phdude research "<query>" [--question RQ-n] [--provider p[,p]] [--from YYYY] [--limit N] [--allow-network]
phdude research list [--state candidate|accepted|dismissed] [--question RQ-n]
phdude research show CAND-id
phdude research accept CAND-id [--type article|preprint|…]     # creates SRC (newSource with identifiers), links candidate.accepted_as, event
phdude research dismiss CAND-id --reason "…"                     # event
phdude research-fresh [--question RQ-n] [--allow-network]        # re-run searches older than stale_after_days (or all with --all); report new candidates only
phdude freshness [--json]                                        # per question: last search, days ago, stale?; per source: age; overall summary
phdude edit <id> --json '<fields>'                               # non-identity fields of a non-canonical object (from the v0.2 backlog); VALIDATION on identity fields; event
```
- `research` with no `--question` still records the search (question null). `accept` requires `title`, `authors`, `year` (VALIDATION with hint to `edit` after acceptance if the provider lacked them? No: accept fills what it has; `cite check` reports missing fields afterwards).
- `next` gains `stale-search` (medium: a question whose last search is older than `stale_after_days`, or never searched) and `candidates-pending` (medium: ≥5 candidates in state `candidate`). `gaps` gains kind `question-never-searched` (medium) and `stale-search` (low).
- `status` gains a "Literature" block: candidates by state, searches, stale count.

### 3.5 Skills

- New `skills/research/SKILL.md` (`permissions.network: allowed` — the first network skill; installed only when policy allows, per v0.2 enforcement): how to write queries per RQ (use the RQ text, key terms, method terms from packs), run per provider, review candidates with the researcher (title/venue/year/abstract), accept with a reason, dismiss with a reason, never fabricate, never accept without reading at least the abstract, respect `preprints.require_approval`.
- `literature` skill: freshness section. `phdude-core`: network rule ("network only through `phdude research`; never fetch on your own"). `next` skill: new rules.

### 3.6 Provenance and events

Accepted sources carry `provenance: { method: 'imported', derived_from: [] }` plus `ext.research: { candidate: CAND-id, provider, external_id, accepted_by }`. Events: `search`, `research` (accept/dismiss), `edit`.

## 4. Architecture notes

- `deps.fetch` and `deps.env` injected in `run.js`; application never imports adapters (providers injected as `deps.providers: SearchProvider[]` built from the policy's list).
- Domain: `src/domain/candidates.js` (dedup, scoring, filtering), `src/domain/freshness.js` (pure).
- No new runtime dependency (global `fetch`, `AbortController`, existing XML walker).
- Object schemas: `candidate.json`, `search.json`; `source.json` unchanged. Workspace version stays 2 (additive dirs); `init` creates `knowledge/candidates` and `research/searches`; a migration is not needed (dirs created lazily by the store when writing).

## 5. Testing

Unit: dedup/scoring/filters, freshness math, each provider's mapping from fixtures. Contract: all five providers through `searchProviderContract` with fakeFetch (success, empty, 429 retry, 500, malformed, abort). Integration: research → candidates + search written + one event per provider; accept → SRC + candidate updated; dismiss; research-fresh only-new logic; policy refusal without network; `edit` guards. Golden: `freshness` on the example (example gains one search and two candidates via the generator with a fake provider). E2E: full flow with `deps.fetch` faked via `PHDUDE_FAKE_FETCH=<fixture dir>` env hook in run.js (test-only, documented as internal).

## 6. Definition of done

`npm test` green offline; live smoke against OpenAlex and Crossref documented in the report (run once by the implementer with `PHDUDE_LIVE_TESTS=1`); docs (cli, workspace, extending: SearchProvider port + contract suite), README ("finding literature" section), CHANGELOG 0.3.0, ADR 0007 network policy and provider ports; tag v0.3.0.
