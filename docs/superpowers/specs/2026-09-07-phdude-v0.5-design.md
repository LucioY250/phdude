# PhDude v0.5 — Analysis & Visualization — Design Spec

**Date:** 2026-09-07
**Status:** Approved for implementation (user directive: finish everything to v1.0)
**Scope source:** `docs/PRD.md` v1.2 §115 (v0.5), §26–§28, §56, §75, §102–§103.
**Baseline:** v0.4.0.

---

## 1. Goal

Analyses, tables and figures become first-class, reproducible research objects with lineage: a dataset is hashed and profiled, an analysis is a declared script run under an explicit execution policy, its results are recorded as `RESULT` objects, and tables and figures are generated from results or datasets by reproducible generators. `phdude repro check` tells the researcher what is stale. The core never assumes statistics; the analysis skill and the method packs supply the judgment.

Success condition:

> On the example workspace with `execution.enabled: true` (or `--allow-exec`): `phdude data add data/survey.csv` profiles and registers a dataset; `phdude analyze add` declares a Node script that reads it and writes `results.json`; `phdude analyze run` executes it, records the run with input/output hashes, and creates `RESULT-*` objects from `results.json`; `phdude table build` renders a Markdown/LaTeX/CSV table from a result; `phdude figure build` runs a generator that writes an SVG with alt text; editing the dataset makes `phdude repro check` (and `next`) report the analysis, table and figure as stale; with execution disabled every run refuses with a clear hint. All of it runs in CI with Node as the only runtime.

## 2. Out of scope

Statistical methods inside PhDude (they live in the researcher's scripts and packs' skills), DOCX/PPTX/XLSX output (v0.6), automatic chart drawing beyond the reference generator (packs may ship generators later), notebooks.

## 3. Deliverables

### 3.1 Execution policy (PRD §75, §71)

- `.phdude/research-policy.yaml` gains `execution: { enabled: false, runtimes: { node: node, python3: python3, Rscript: Rscript }, timeout_seconds: 600 }`. A run is allowed only with `execution.enabled` or `--allow-exec`; otherwise `PhdudeError('POLICY', 'script execution is disabled', 'set execution.enabled: true in .phdude/research-policy.yaml or pass --allow-exec')`.
- `src/ports/analysis-runner.js`: `{ name, async available(runtime) → boolean, async run({ runtime, script, args, cwd, env, timeoutMs }) → { exitCode, stdout, stderr, durationMs } }` with a contract suite (echo script success, non-zero exit propagated, timeout → TOOL_MISSING with hint, unavailable runtime → TOOL_MISSING). Adapter `src/adapters/execution/local.js` using `execFile` (argument arrays only), `cwd` = workspace root, minimal `env` (`PATH`, `HOME`, `LANG`, `PHDUDE_WORKSPACE`, `PHDUDE_ANALYSIS`), no shell. Every run appends one event `{ op: 'analyze', ids: [ANALYSIS-id, …RESULT ids], summary }`.

### 3.2 Datasets

- `DATASET-<hash10 of file bytes>` in `knowledge/datasets/`: `path` (workspace-relative under `data/`), `hash`, `bytes`, `format` (csv|tsv|json|xlsx|other), `profile` (for csv/tsv/xlsx via the existing parsers: `rows`, `columns: [{ name, inferred_type: number|string|boolean|date|empty, missing, distinct(≤ 50 shown) }]`), `description?`, `license?`, `sensitive: boolean` (default false; when true, `profile.samples` is omitted), `state`.
- `phdude data add <path> [--json '{description, license, sensitive}']`, `data list|show|profile <id>`, re-adding unchanged bytes is a no-op; changed bytes make a new dataset id (versions linked via `versions_of` on the same path, as artifacts do).

### 3.3 Analyses and results (PRD §26, §102)

- `ANALYSIS-<hash10 of name>` in `analysis/`: `name`, `runtime` (node|python3|Rscript|other), `script` (workspace-relative under `analysis/`), `args[]`, `inputs: [DATASET ids]`, `outputs: { results: 'analysis/out/<name>/results.json', files: [paths] }`, `params` (free object), `runs: [{ at, exit, duration_ms, input_hashes: {id: hash}, output_hashes: {path: hash}, results: [RESULT ids] }]`, `state`.
- Contract for scripts: they receive `PHDUDE_ANALYSIS=<id>` and `PHDUDE_WORKSPACE`, read their inputs from `data/`, and write `results.json` as `{ "results": [ { "key": "…", "summary": "…", "values": { … }, "unit"?: "…" } ], "tables"?: [...], "notes"?: [...] }`. PhDude turns each result into `RESULT-<hash of summary+analysis>` with `from: ANALYSIS-id`, `values`, `ext.analysis: { key, run_at }`, state `candidate`; re-running with identical values is a no-op per result; changed values make a new RESULT and the old one is marked `superseded_by`? Ruling: keep old results, add `state: rejected` to results whose key reappears with different values, and reference the new one.
- `phdude analyze add --json`, `analyze list|show <id>`, `analyze run <id> [--allow-exec] [--force]` (refuses when inputs unchanged since the last successful run unless `--force`, reporting "up to date"), `analyze runs <id>`.
- Lineage: RESULT → ANALYSIS (`from`), ANALYSIS → DATASET (`inputs`), evidence may cite a RESULT (existing), claims cite evidence.

### 3.4 Tables (PRD §28)

- `TABLE-<hash10 of name>` in `tables/`: `name`, `caption`, `source: { result: RESULT-id } | { dataset: DATASET-id, columns?: [names], limit?: n }`, `columns: [{ key, label, format?: number:2|percent:1|text }]`, `formats: [md, latex, csv]`, `outputs: { md: 'tables/out/<name>.md', latex: …, csv: … }`, `runs`.
- `phdude table add --json`, `table build <id> [--format …]` (pure renderers in `src/domain/tables.js`: Markdown, LaTeX `booktabs`, CSV; deterministic; escapes LaTeX specials), `table list|show`. Output files record the source hash; stale when the source RESULT/DATASET changed.

### 3.5 Figures (PRD §27, §100)

- `FIG-<hash10 of name>` in `figures/`: `name`, `caption`, `alt` (required, non-empty; PRD §100), `generator: { runtime, script, args }`, `inputs: [RESULT|DATASET ids]`, `outputs: [{ path, format: svg|png|pdf }]`, `runs`.
- `phdude figure add --json`, `figure build <id> [--allow-exec]` (runs the generator through the runner; verifies outputs exist and hashes them), `figure list|show`, `figure check` (missing alt, outputs missing, stale inputs).
- Reference generator shipped in the package: `generators/bar-chart.mjs` (Node, no deps) producing an accessible SVG (title, desc, axis labels, dataviz-neutral palette) from a RESULT's `values` or a dataset column — enough for the example and CI; packs may ship more.

### 3.6 Reproducibility check and next rules (PRD §36, §67)

- `phdude repro check [--json]`: for every analysis, table and figure: `up-to-date | stale (input <id> changed) | never-run | missing-output`; exit 0 always (report), `--json` structured. `next` gains `analysis-stale` (high when a RESULT cited by a supported/canonical claim is stale, else medium), `figure-missing-alt` (medium), `never-run` (low). `gaps` gains `result-uncited` (low: result not cited by any evidence).
- `status` gains an "Analysis" block (datasets, analyses, results, tables, figures, stale count).

### 3.7 Skills and packs

- `skills/analysis/SKILL.md` (permissions: `execution: allowed` — extend the skill contract schema with `permissions.execution: none|allowed`; installed only when policy `skills.allow_execution` is true): PRD §26 seven steps; declare analyses via the CLI, never run scripts directly; explain assumptions; write `results.json` per contract; check `repro`. `skills/figures/SKILL.md`: dataviz rules (one message per figure, alt text that states the finding, no 3D, colorblind-safe palette, units on axes), how to declare and build figures. Method packs `quantitative`/`qualitative` gain an "Analysis" section pointing at typical scripts and reporting standards (no code). `phdude-core`: execution rule.

## 4. Architecture notes

- Ports: `AnalysisRunner`. Adapters: `execution/local.js`. Domain: `datasets.js` (profile from parsed tables), `analysis.js` (run bookkeeping, results diffing), `tables.js` (renderers), `figures.js` (validation, staleness), `repro.js` (staleness graph). Application: `data.js`, `analyze.js`, `table.js`, `figure.js`, `repro.js`.
- Schemas: `dataset.json`, `analysis.json`, `table.json`, `figure.json`; `result.json` gains optional `ext.analysis`, `superseded_by`; `skill.json` permissions gains `execution`. Workspace version → 3 with migration 0002 (adds `execution` and `skills.allow_execution: false` to research-policy? Policy files are not entities; migration 0002 adds the policy keys when missing and creates `knowledge/datasets`, `analysis/out`, `tables/out`, `figures/out` dirs).
- No new runtime dependency; SVG generator is plain Node.

## 5. Testing

Unit: profiling, results diffing, table renderers (golden md/latex/csv), figure validation, repro staleness, policy. Contract: runner (with a Node echo script; python3/Rscript skipped when absent), skill contracts incl. execution permission. Integration: full data → analyze → table → figure flow with `execution.enabled` on a temp workspace (Node runtime only); refusal when disabled; stale detection after editing the dataset. Golden: `repro check` and the reference figure SVG on the example. E2E: the flow through the CLI with `--allow-exec`.

## 6. Definition of done

Example gains `data/survey.csv`, one analysis (Node script committed under the example's `analysis/`), one result, one table, one figure with alt text; README "Analysis and figures" section; docs (cli, workspace, extending: AnalysisRunner port, script contract, generators); CHANGELOG 0.5.0; ADR 0009 execution policy and results contract; migration 0002; tag v0.5.0.
