# PhDude v0.3 Research Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v0.3: an opt-in, audited network policy; a SearchProvider port with five adapters testable offline; candidates and recorded searches; accept/dismiss into the source registry; freshness tracking; `research-fresh`; `phdude edit`; the matching skills, docs and next/gaps rules.

**Architecture:** Same layering. `deps.fetch`, `deps.env` and `deps.providers` are injected in `run.js`; application code never touches the network directly. Providers are adapters over global `fetch` with timeouts, one bounded retry and strict response validation. Candidates and searches are ordinary entity-per-file objects with content-derived ids.

**Tech Stack:** Node ≥ 22 (`fetch`, `AbortController`), no new runtime dependency.

**Spec:** `docs/superpowers/specs/2026-09-07-phdude-v0.3-design.md`

## Global Constraints

- All v0.1/v0.2 constraints (layering test, three deps, `execFile` only, atomic writes, one event per mutating use case, strict flags, typed errors, exit codes, guard `assertUpToDate` on every mutator, example + goldens regenerated when output changes).
- No network call without `network.enabled` or `--allow-network`; every call → one `search` event; only the query leaves the machine.
- Tests never touch the network: `fakeFetch` fixtures only; live tests behind `PHDUDE_LIVE_TESTS=1` and skipped in CI.
- Ids: `CAND-<10hex>` of `candidate\n<provider>:<external_id>`; `SEARCH-<10hex>` of `search\n<normalized query>|<question or ''>`.
- Commit per task with the repo's trailers; do not push.
