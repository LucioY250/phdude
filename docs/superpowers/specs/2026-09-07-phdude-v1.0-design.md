# PhDude v1.0 — Public Release — Design Spec

**Date:** 2026-09-07
**Status:** Approved for implementation (user directive: finish everything to v1.0)
**Scope source:** `docs/PRD.md` v1.2 §118 (v1.0), §57–§61, §88, §90, §93–§97, §105, §109, §119–§120.
**Baseline:** v0.7.0.

---

## 1. Goal

Stabilize and publish. v1.0 adds no new research capability; it freezes the contracts researchers and extension authors depend on, proves field agnosticism with cross-field example projects, adds a third agent host, hardens CI and supply chain, documents migration and extension paths, and ships an installable package with a release workflow.

Success condition:

> `npm test` runs the full pyramid including three cross-field example workspaces built by generators; every public schema carries `stability: stable` and a documented compatibility promise; every port has a documented contract suite and an example third-party implementation in `examples/extensions/`; a third host (OpenCode) installs and its contract passes; `phdude migrate` upgrades a v0.1 and a v0.2 fixture to the current version; `docs/` contains migration, extension, skill-authoring and pack-authoring guides; CI runs format, lint, tests, schema validation, skill validation, `npm pack --dry-run`, dependency audit and a release job that publishes to npm on a `v*` tag when `NPM_TOKEN` is present (skipped otherwise); the repository is ready to be made public (LICENSE, CODE_OF_CONDUCT, CONTRIBUTING, SECURITY, issue templates).

## 2. Deliverables

### 2.1 Stable contracts (PRD §57–§61)

- `schemas/*.json` gain `"x-phdude": { "stability": "stable", "since": "0.x" }`; a `tests/contracts/schema-stability.test.js` snapshot of every schema's required fields and enums (`tests/fixtures/schema-snapshot.json`) fails on any change without a matching `x-phdude.since` bump and a migration — the freeze mechanism.
- Ports (`SearchProvider`, `DocumentParser`, `DocumentRenderer`, `AgentHost`, `AnalysisRunner`, `ResearchPack`, `ResearchSkill`) documented in `docs/extension-api.md` with lifecycle, error behavior, stability status, and the contract-suite invocation; `examples/extensions/` contains a minimal third-party provider, parser, renderer and pack, each exercised by the contract suites in CI.
- CLI: `phdude --version` prints `1.0.0`; `docs/cli.md` marks each command `stable`; exit codes and `--json` error shape frozen (`tests/contracts/cli-json-shape.test.js`).
- SemVer policy and deprecation policy in `docs/versioning.md`; CHANGELOG 1.0.0 lists every breaking change since 0.1.

### 2.2 Third agent host (PRD §109, §118)

- `src/adapters/agents/opencode.js`: OpenCode reads `AGENTS.md` and supports custom commands under `.opencode/command/*.md`; the host writes the compact `AGENTS.md` variant (index) and command files mirroring the Claude Code templates; contract test via `agentHostContract`; `init --agents opencode`. Gemini CLI documented as "works via AGENTS.md" (no host-specific files) with a smoke note.

### 2.3 Cross-field examples (PRD §88, §120)

- `examples/quantitative-social-science/`, `examples/machine-learning/`, `examples/qualitative-humanities/` generated by `scripts/make-examples.mjs` (one generator with three profiles) using real CLI use cases: each with sources, claims, a method, a question, one conflict or contradiction, a manuscript section, a dataset+analysis+figure where the field fits (ML: benchmark results table; humanities: archival sources, no statistics; social science: survey dataset), applied packs; golden `status`, `next`, `gaps`, `health`, `ready` per example; parity tests. These prove field agnosticism: the core never branches on field.

### 2.4 Docs (PRD §93–§95)

- `docs/migration.md` (workspace versions, what each migration does, how to write one), `docs/extension-api.md`, `docs/skills-authoring.md` (SKILL.md convention + `phdude:` contract + tests), `docs/packs-authoring.md` (field/method/venue), `docs/agents.md` (Claude Code, Codex, OpenCode, Gemini CLI setup), README final pass (install from npm once published; badges; a 90-second tour), `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md` (Contributor Covenant), `SECURITY.md` (reporting), `.github/ISSUE_TEMPLATE/*`, `.github/PULL_REQUEST_TEMPLATE.md`.

### 2.5 CI, supply chain, release (PRD §90, §97)

- `ci.yml`: matrix Node 22/24 × ubuntu; add `windows-latest` on Node 22 for the unit+contract subset (path handling); steps: format, lint, `npm audit --audit-level=high` (advisory), schema/skill validation, tests, `npm pack --dry-run`, example parity; `permissions: contents: read`.
- `release.yml`: on `v*` tag: build, test, `npm publish --provenance --access public` when `NPM_TOKEN` secret exists (job skipped with a notice otherwise), create GitHub release notes from CHANGELOG.
- `package.json`: `"publishConfig": { "access": "public" }`, `files` audited, `engines`, `repository`, `keywords`.
- Dependabot config for npm and actions.

### 2.6 Non-goals reaffirmed (PRD §119)

No cloud, no accounts, no web UI, no vector DB, no detector scores. `docs/non-goals.md` mirrors PRD §119 for contributors.

## 3. Testing

Everything above is tested by construction: stability snapshots, contract suites over example extensions, host contract for OpenCode, generators + parity for three examples, Windows subset, release workflow dry-run job (`workflow_dispatch` with `dry_run: true`).

## 4. Definition of done

`main` tagged `v1.0.0`; release created with notes; release workflow ran (publish step skipped or succeeded depending on the secret); README states the install path that actually works at that moment; the repository is one setting away from public, with a checklist in the release notes for the owner.
