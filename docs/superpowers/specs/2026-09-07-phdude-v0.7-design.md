# PhDude v0.7 — Reviewer — Design Spec

**Date:** 2026-09-07
**Status:** Approved for implementation (user directive: finish everything to v1.0)
**Scope source:** `docs/PRD.md` v1.2 §117 (v0.7), §37, §39–§42, §41c, §30c.
**Baseline:** v0.6.0.

---

## 1. Goal

PhDude reviews the project like a demanding colleague: a citation auditor that verifies identifiers against the registry and, when the network policy allows, against Crossref; methodology and "Reviewer #2" skills that produce structured, evidence-linked review findings the researcher can accept into the workspace; an explainable Research Health score across the PRD's dimensions; and `phdude ready`, the submission-readiness verdict that composes health, profile checks, gaps, repro and prose quality. External skills load under least privilege.

Success condition:

> On the example workspace: `phdude audit citations` reports unresolved or malformed citations and, with network enabled, DOI metadata mismatches; `phdude review methodology` and `phdude review reviewer2` hand the agent a bounded review context and accept a findings file back through the CLI as `REVIEW-*` objects with severities and linked ids; `phdude health` prints eight dimension scores, each with the observations behind it, and never a "humanity" or detector score; `phdude ready --profile ieee` prints a pass/fail verdict with the blocking items; an external skill directory dropped into `.phdude/skills/` loads with least privilege and appears in `doctor`.

## 2. Out of scope

LLM-side scoring of prose (deterministic lint only), plagiarism detection, journal submission APIs, v1.0 stabilization work (next version).

## 3. Deliverables

### 3.1 Citation auditor (PRD §37)

- `phdude audit citations [--allow-network] [--json]`: offline checks = `cite check` findings + manuscript-level checks (every `[@key]` in every section resolves; claims asserted in sections cite at least one evidence-bearing source; sources cited only in candidate/dismissed state flagged); online (policy-gated, v0.3 http + Crossref adapter `works/<DOI>`): DOI resolves, title similarity ≥ 0.8 (normalized token Jaccard) else `mismatch`, year matches ±1 else `warn`, retracted flag when Crossref `update-to` contains a retraction → `block`. Findings stored as `REVIEW-*` objects (kind `citation`), one `audit` event per run.

### 3.2 Review objects and reviewer skills (PRD §40–§41)

- `REVIEW-<hash10 of kind+target+message>` in `reviews/`: `kind` (citation|methodology|reviewer2|reproducibility|custom), `target` (id or `manuscript:<section>` or `project`), `severity` (block|major|minor|note), `message`, `evidence: [ids]`, `suggested_command?`, `status` (open|accepted|dismissed|resolved), `by` (actor), `mode` (lite|full|ruthless).
- `phdude review <kind> [--target …]` assembles the review context (like `write`: the relevant claims/evidence/methods/results/sections within a budget) and prints the review contract; the agent writes findings as JSON; `phdude review submit --file findings.json` validates and stores REVIEW objects (one event); `review list|show|accept|dismiss|resolve <id>`; `next` gains `reviews-open` (high when any `block`/`major` open).
- Skills: `skills/methodologist/SKILL.md` (design–question fit, sampling, instruments, validity threats, reporting standards from packs), `skills/reviewer2/SKILL.md` (adversarial: unsupported claims, overclaiming, missing alternatives, weak comparisons, contradictions ignored; must cite ids for every finding; ruthless mode = every finding at least `major`), `skills/reproducibility-reviewer/SKILL.md` (uses `repro check`, analysis contracts, data availability). Packs' `reviewers[]` names map to sections in these skills (medicine → CONSORT/STROBE/PRISMA checklists as references).

### 3.3 Research Health (PRD §39)

- `phdude health [--json]`: dimensions and deterministic formulas (documented in the output): Literature Coverage (questions with ≥1 supported claim, sources per question, freshness), Evidence Strength (claims by state and evidence strength), Methodological Integrity (questions with a method, methods with limitations declared, open methodology reviews), Citation Quality (cite/audit findings), Freshness (stale searches), Reproducibility (repro check), Consistency (open conflicts, disputed pairs), Academic Prose Quality (mean of section prose reports; null when no manuscript). Each 0–100 with the observations list; the overall is a weighted mean with weights in `.phdude/research-policy.yaml health.weights` (defaults documented). Explicitly no detector/humanity score (PRD §30c); the command refuses `--detector`.
- Stored snapshot `reports/health-<date>.yaml`? Ruling: health is computed on read and optionally saved with `--save` into `reports/health.yaml` (latest only) for trend display (`health --trend` compares to the saved one).

### 3.4 Submission readiness (PRD §42)

- `phdude ready [--profile <venue>] [--json]`: composes: profile check (block items), health thresholds from the policy (`ready.min_health: 70`, `ready.require: [no-open-conflicts, no-disputed-pairs, no-block-reviews, all-sections-approved, figures-alt, repro-clean, citations-clean]`), gaps (high) and lists blocking items with the command to fix each; exit 0 when ready, 2 otherwise. Never writes.

### 3.5 External skills (PRD §41c)

- `discoverSkills` already loads `.phdude/skills/*`; v0.7 adds `phdude skills install <path|git-url>` (copies a skill dir; git clone via `execFile('git', ['clone', '--depth', '1', …])` only with `--allow-network`), validates the contract, refuses purpose strings mentioning detector evasion (regex over SKILL.md: /detect(or|ion)\s+(evasion|bypass)|humaniz/i → POLICY), records provenance in `.phdude/skills-lock.yaml` (name, source, hash), `skills list|remove`. `doctor` shows external skills with their source.

## 4. Architecture notes

- Domain: `reviews.js`, `health.js` (pure formulas), `ready.js`, `audit.js` (offline part), `similarity.js`. Application: `audit.js`, `review.js`, `health.js`, `ready.js`, `skills.js` (+install/remove). Adapters: reuse search/http + a `crossref-doi.js` lookup.
- Schemas: `review.json`, `skills-lock.json`; policy keys `health.weights`, `ready.*`. Workspace version → 5 with migration 0004 (creates `reviews/`, policy keys).
- Review modes (`phdude mode`) finally bite: `lite` runs only block-severity checks in `ready`; `full` default; `ruthless` promotes `major` → `block` in `ready` and makes prose-lint findings block in `submit`.

## 5. Testing

Unit: health formulas on synthetic snapshots (bounds, weights, null prose), ready composition, audit offline rules, similarity, review transitions. Contract: new skills validate; external skill install rejects detector-purpose text; crossref DOI lookup through the search contract style with fixtures. Integration: audit offline on the example; review submit → objects + event; health/ready on the example; install a skill from a temp dir. Golden: `health` and `ready` on the example. E2E: ready exit codes.

## 6. Definition of done

Example gains one review, health report golden; README "Reviewing and readiness"; docs; CHANGELOG 0.7.0; ADR 0011 research health formulas and no-detector rule; migration 0004; tag v0.7.0.
