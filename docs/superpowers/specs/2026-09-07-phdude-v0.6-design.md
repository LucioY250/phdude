# PhDude v0.6 — Document Factory — Design Spec

**Date:** 2026-09-07
**Status:** Approved for implementation (user directive: finish everything to v1.0)
**Scope source:** `docs/PRD.md` v1.2 §116 (v0.6), §31–§33, §35–§36, §43, §103, §108 (document tool adapters).
**Baseline:** v0.5.0.

---

## 1. Goal

The canonical manuscript (v0.4) plus a publication profile plus a template produce the deliverable files: DOCX, PDF, LaTeX, Markdown, and presentation/spreadsheet outputs, incrementally, reproducibly, with the bibliography generated from the citation registry. Publication profiles ship as Venue Packs (IEEE, ACM, generic thesis) and `phdude adapt --to <venue>` restructures the manuscript for a venue through the same writing gates. External tools (Pandoc, LaTeX) are optional adapters; without them PhDude still builds Markdown and LaTeX sources and says exactly what is missing.

Success condition:

> On the example workspace: `phdude build --format md` always works; with Pandoc installed, `phdude build --format docx --profile generic-thesis` produces `outputs/<name>.docx` from the approved sections with a bibliography rendered from `references.bib` via CSL; `phdude build --format latex --profile ieee` produces a compilable `.tex` using the IEEE venue pack's template; a second `build` with no changes does nothing (incremental); `phdude adapt --to acm` produces a section-mapping plan and a revised `manuscript.yaml` for the target venue, and `phdude ready`-style checks for the profile (word limits, required sections, figure formats) are reported by `phdude profile check`. `phdude table build --format docx` and `phdude present outline` produce DOCX tables and a PPTX outline through Pandoc; `phdude table build --format xlsx` writes a real XLSX without any external tool.

## 2. Out of scope

Reviewer skills and Research Health (v0.7), the full `phdude ready` verdict (v0.7 composes it), journal submission systems, Word template round-tripping beyond Pandoc `--reference-doc`, LaTeX template editing.

## 3. Deliverables

### 3.1 DocumentRenderer port and adapters (PRD §48, §108)

- `src/ports/document-renderer.js`: `{ name, formats: string[], async available() → { ok, version?, hint? }, async render({ input: { markdownPath, bibPath?, cslPath?, referenceDoc?, template?, metadata }, output: { path, format }, cwd }) → { path, warnings } }` + contract suite (available reports honestly; render md→md copies; unavailable → `TOOL_MISSING` with install hint; bad input → VALIDATION).
- Adapters: `src/adapters/render/pandoc.js` (docx, pptx, html, latex, md; `--citeproc` with `--bibliography` and `--csl`; `--reference-doc` for DOCX/PPTX templates; execFile only), `src/adapters/render/latex.js` (pdf via `latexmk -pdf` or `pdflatex` twice + `bibtex`/`biber` when present), `src/adapters/render/markdown.js` (built-in: concatenates sections, resolves `[@key]` into a plain "References" list from the registry using a simple author-year style when no Pandoc — always available). `buildRenderers({ execFile, env })` picks by format with a documented precedence.
- `doctor` reports each renderer's availability and version.

### 3.2 Publication profiles as Venue Packs (PRD §32, §7)

- `packs/venues/<name>/pack.yaml` (`kind: venue`) plus `profile.yaml` (`schema: phdude.profile`, `version: 1`): `name`, `display`, `document_class` (latex), `citation_style` (CSL file path within the pack or a built-in name), `sections: [{ id, title, required, order, max_words? }]`, `abstract: { max_words }`, `page_limit?`, `figures: { formats: [pdf, png], min_dpi? }`, `tables: { style }`, `references: { style }`, `templates: { docx?: path, pptx?: path, latex?: path }`, `writing: { first_person: never|sparing|natural, tense_abstract?, terminology_map?: {from: to} }`.
- Shipped: `generic-thesis` (IMRaD + conclusions, generous limits, APA-like CSL), `ieee` (IEEE structure, `IEEEtran` class, IEEE CSL, 8-page hint), `acm` (`acmart` class, ACM CSL). CSL files vendored under the pack (CC-BY-SA notice preserved); templates: minimal `.tex` templates per class and a `reference.docx` generated by Pandoc at build time if absent.
- `phdude packs apply ieee` sets `phdude.yaml venues: [ieee]` (schema gains `venues[]`); `manuscript.yaml target_profile` selects the active one; `phdude profile list|show|check [--profile]`: check evaluates required sections, order, word counts per section (counting the section body without markers), abstract limit, figure formats present, references style set; findings with severity, exit 2 on `block`.

### 3.3 Build (PRD §33, §35–§36, §103)

- `phdude build [--format md|docx|pdf|latex|html] [--profile <venue>] [--sections a,b] [--force]`: assembles `outputs/<slug>/manuscript.<fmt>` from approved (or all, with `--include-drafts`) sections in profile order; front matter metadata (title, authors from `authors/`, date fixed from `manuscript.yaml` `date` or the last approval event for reproducibility, abstract); bibliography from `cite export` (regenerated into `outputs/<slug>/references.bib`); figures copied/converted as the profile demands (svg→pdf via `rsvg-convert` when available else warning); tables from `tables/out`.
- Incremental: `.phdude/cache/build/<slug>/<format>.json` records the hash of every input (sections, bib, figures, profile, template, renderer version); unchanged ⇒ `up to date`, no render, no event; `--force` overrides. One `build` event per actual render with the output hash.
- Reproducibility: identical inputs and renderer versions ⇒ identical bytes for md/latex/html; DOCX/PDF equality is best-effort (timestamps normalized where Pandoc allows `--metadata date`); documented in ADR.

### 3.4 Presentations and spreadsheets (PRD §31, §116)

- `phdude present outline [--from manuscript|claims] [--profile]` writes `outputs/<slug>/outline.md` (one slide per section/claim with the claim's strongest evidence as bullets) and, with Pandoc, `outline.pptx` (`--reference-doc` from `templates/presentations/` when present).
- `phdude table build --format xlsx|docx`: XLSX via a built-in minimal SpreadsheetML writer (`src/adapters/render/xlsx.js`, fflate `zipSync`, deterministic timestamps, shared strings, numbers typed); DOCX tables via Pandoc from the Markdown table.

### 3.5 Venue adaptation (PRD §43)

- `phdude adapt --to <venue> [--apply]`: computes a plan: section mapping (source section → target section by id/title synonyms table in the venue pack, unmapped → "needs decision"), word-limit deltas, abstract limit, figure format conversions, terminology map hits, citation style change. Without `--apply` prints the plan; with `--apply` writes a new `manuscript/manuscript.<venue>.yaml` (target profile, mapped sections referencing the same files) and marks sections that exceed limits as `revised` requiring a `deslop`/`write` pass; content rewriting itself is agent work through the v0.4 pipeline (skill `venue-adapt`), never automatic.

### 3.6 Templates registry (PRD §31)

- `templates/{university,journals,conferences,presentations,custom}/` in the workspace; `phdude template list|add <path> [--kind docx|pptx|latex]|use <name> --for <profile>` registers templates in `.phdude/templates.yaml` (path, kind, hash); build passes them to the renderer; `template check` validates a DOCX template has the styles Pandoc needs (Heading 1–3, Body Text, Caption) by unzipping `word/styles.xml` with the existing OOXML tooling.

## 4. Architecture notes

- Ports: `DocumentRenderer`. Adapters: `render/{pandoc,latex,markdown,xlsx}.js`. Domain: `build.js` (assembly + hashing + incremental plan), `profiles.js` (checks), `adapt.js` (mapping plan), `outline.js`, `xlsx.js` writer, `citations-md.js` (plain reference list). Application: `build.js`, `profile.js`, `adapt.js`, `present.js`, `template.js`.
- Schemas: `profile.json`, `templates-registry.json`; `project.json` gains `venues[]`; workspace version → 4 with migration 0003 (adds `venues: []`, `.phdude/templates.yaml` empty registry).
- No new runtime dependency. Pandoc, LaTeX, rsvg-convert are optional and probed with `execFile`.
- Skills: `venue-adapt` (plan → agent rewrites through write/deslop), `build` (how to run builds, read `profile check`, never hand-edit outputs), updates to `phdude-core`, `write`.

## 5. Testing

Unit: build plan/hashing, profile checks, adapt mapping, outline, xlsx writer (unzip and check sheet XML), markdown citations. Contract: renderer suite over markdown (always) and pandoc/latex (skipped when unavailable; CI installs pandoc via apt to exercise docx/html/latex; PDF skipped unless texlive present — install `texlive-latex-base` in CI only if under 2 min, else skip). Golden: `build --format md` and `--format latex --profile ieee` outputs on the example; `present outline` md. E2E: build twice → second is up to date; adapt plan JSON; profile check block on an over-limit abstract.

## 6. Definition of done
